# Theming

Sigil ships two themes — `light` and `dark` — defined as token objects in
`src/widgets/shared/theme.ts`. The rendering rule is the same everywhere: widgets
read CSS custom properties (`--sigil-*`); the theme just decides which set of
values those properties hold.

## How a theme is selected

There are three selection paths, in priority order, all emitted as CSS by
`theme.ts` and mirrored by `useTheme()` for the tokens charts read in JS:

1. **Dev / catalog — force a theme.** `renderForcedThemeCss()` emits the
   tokens keyed off an attribute:

   ```css
   html:root[data-sigil-theme="light"] { /* light tokens */ }
   html:root[data-sigil-theme="dark"]  { /* dark tokens  */ }
   ```

   Setting `data-sigil-theme="dark"` on the document overrides everything
   below. This is exactly what the toolbar toggle drives. The `html:root`
   selector keeps it above path 2 regardless of stylesheet order.

2. **Production — follow the host.** An MCP Apps host reports its theme in the
   host context. `widget-shell` reads it on connect and on every
   `hostcontextchanged` notification and calls `applyDocumentTheme`, which sets
   `data-theme` on `<html>`. `renderThemeCss()` answers with
   `:root[data-theme="light"]` / `:root[data-theme="dark"]` blocks, and
   `useTheme()` watches the attribute. So Claude in dark mode on a light OS
   renders dark widgets.

3. **Fallback — follow the OS.** With no host theme, `renderThemeCss()` sets
   the light tokens under `:root` and overrides them under
   `@media (prefers-color-scheme: dark)`.

Only the theme *name* is taken from the host. Its colour and surface variables
are not: Sigil's palette is validated against Sigil's own backgrounds
(`src/__tests__/palette.test.ts`), and a foreign background would void those
contrast guarantees.

## How the toolbar toggle works

`.storybook/preview.tsx` does two things at load:

- Injects both stylesheets once (base tokens via `installThemeStyles()`, plus
  the forced-theme override CSS) — the same pair the sandbox's `App.tsx` injects.
- Registers `@storybook/addon-themes`' `withThemeByDataAttribute` decorator,
  configured to write `data-sigil-theme`:

  ```ts
  withThemeByDataAttribute({
    attributeName: "data-sigil-theme",
    themes: { light: "light", dark: "dark" },
    defaultTheme: "light",
  });
  ```

So flipping the theme in the toolbar sets `data-sigil-theme`, the forced-theme
CSS takes over, and every story re-renders in the chosen theme — **no
theming-specific code in the stories themselves**, and no change to any widget
View. The same decorator contract the addon expects already existed in the
codebase, which is why theming wired up with zero new theming code.

## Verifying

The bar chart and pie chart are the quickest visual confirmations: toggle the
toolbar and the surfaces, text, grid lines, and series colors all swap together.
